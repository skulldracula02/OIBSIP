# Predicting House Prices with Linear Regression

An end-to-end regression project: from raw data and EDA, through cleaning and encoding,
to a trained/evaluated linear model and coefficient interpretation — with a Ridge/Lasso
comparison as a bonus.

## Results at a glance (test set, 20% hold-out)

| Model | Test R² | Test RMSE |
|---|---|---|
| Linear Regression (OLS) | **0.961** | $24,224 |
| Ridge (best α = 10) | 0.961 | $24,184 |
| Lasso (best α = 1000) | **0.961** | $24,165 |

- **Typical error** ≈ 6.8% of the mean house price.
- Train R² (0.965) and test R² (0.961) are close → the model **generalises**, it does not overfit.
- **Top positive drivers:** `location_Waterfront`, `area`, `quality`.
- **Top negative driver:** `location_Rural`, then `age`.

## About the dataset

The notebook ships with `data/house_prices.csv`, an **Ames-Housing-style** dataset generated by
`data/generate_dataset.py`. It mirrors the structure and behaviour of the Kaggle
*["House Prices: Advanced Regression Techniques"](https://www.kaggle.com/c/house-prices-advanced-regression-techniques)*
(Ames) dataset — 9 columns, a categorical `location`, and genuine missing values — so every
cleaning step is real rather than cosmetic, while remaining fully reproducible offline.

**Using the real Kaggle data instead:** download `train.csv` from the Kaggle competition and
point the load cell at it. The pipeline is written to be transferable; the only extra work is
encoding the many additional categorical columns (~40) and handling the "NA means a category"
fields (e.g. `Alley`, `PoolQC`). For a smaller real dataset you can also swap in the
[California Housing](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_california_housing.html)
data (`fetch_california_housing()`), which is available directly through scikit-learn.

## Key takeaways

1. Linear regression already captures most of the signal in this data — R² ≈ 0.96 with a
   sensible feature set.
2. Location (as one-hot dummies) and area dominate; age pulls price down.
3. Regularisation (Ridge/Lasso) keeps accuracy essentially unchanged here but stabilises
   coefficients against multicollinearity — and Lasso can prune features, which matters far
   more on a wide dataset like the real Ames set (~80 features).
4. Honest limitations: linear/additive assumptions, a mildly skewed target, and
   `area`↔`rooms` collinearity. Next steps: log-transform the target, add interaction terms,
   tune α with `GridSearchCV`, and benchmark against gradient-boosted trees.
